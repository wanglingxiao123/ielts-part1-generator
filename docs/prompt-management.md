# 管理员提示词管理

管理员登录后，顶部进入「提示词管理」。普通用户没有入口；直接请求管理 API 也会被拒绝。管理员身份沿用账户里的 `is_admin`，现有规则是第一个注册成功的账户成为管理员。

1. 选择业务步骤，对照当前生效内容修改草稿。受保护规则可展开查看。
2. 保存草稿。保存不影响正式生成；所有管理员共用一份草稿，并发修改会提示冲突。
3. 可输入合成样例，使用顶部选定模型进行「运行对比」。比较当前发布版本与整套草稿，各执行一次无工具的模型调用，结果不进入正式材料。它不执行完整 Skill、校验和生成流程，不能代替真实材料测试。
4. 核对后点击「发布整套草稿」。以后新任务使用新版本，运行中的任务、原批次补生成以及原修改流程的后续重试继续使用其固定版本。
5. 发布历史可回滚。回滚会留下新的发布记录，仅影响以后新任务。「恢复全部默认文本」先填入本地草稿，仍需保存及发布。

## 试运行记录与默认版本

- 「试运行历史」按测试创建时间倒序展示，每页 20 条。打开记录可查看当时的输入、模型、两侧输出和版本编号；历史结果不代表当前生效版本。
- 「复用输入」只把样例和对应模块填回测试区，不恢复历史提示词，也不自动调用模型。下一次对比使用当前生效版本和当前已保存的草稿。
- 新测试保存输入和所选模块的两侧业务文本快照；输出上方可以展开提示词并复制，两侧输出也可独立复制。展示的是所选模块的业务文本，不是包含全部 Skills 和运行时材料的完整请求。
- 旧记录没有输入时明确提示，禁止复用；提示词快照尽量从原版本恢复，无法恢复时不会拿当前文本代替。
- 发布、回滚或刷新发现生效版本变化时，清空当前试运行输入、输出和编号；记录仍保存在历史中。
- 发布记录里的「恢复内置默认提示词」先展示整套默认内容，确认后创建一条新的生效版本；保留已有发布历史和已保存草稿。它不回退代码或材料。内置默认是当前部署包提供的默认业务文本。

目前开放 4 个角色业务指令和 14 个任务指令。其中三个盲审/可行性任务提供额外业务关注点，默认留空。编辑的是业务文本，不是任意代码模板；运行时材料、变量、JSON 输出契约、工具权限、盲审隔离及确定性检查保持由程序维护。Skill 文本及 Markdown 参考资料只读。不要把账号密钥或客户隐私放入提示词。

## 部署与回退

Web 和 Runtime 必须同时包含 `prompt_config/`。中国区继续使用现有 `IELTS_AUDIO_BUCKET`，配置保存在 `_prompt_config/`：不可变版本 `releases/`、活动指针 `active.json`、草稿 `draft.json`、任务版本绑定 `bindings/`、独立试运行记录 `tests/`。发布指针和草稿使用 S3 条件写；中国区端点已实测拒绝过期 ETag。Runtime 对此目录只读，Web 可写。试运行暂为一次一个，服务重启或超时会显示失败并允许稍后重试。

未设置桶时，本地 Web/Runtime 使用同一 `IELTS_PROMPT_DIRECTORY`；默认是仓库下 `.local/prompt-config/`，需要本机忽略，禁止提交配置内容。它是本地开发存储，不用于分布式部署。

代码回退和提示词回退是两件事：本功能版本内优先在管理页面回滚配置；回退镜像不会自动修改 S3 活动指针。回到本功能之前的镜像会忽略动态配置，重新使用镜像内原始提示词。再次升级会读回原活动指针。已开始任务必须能够读取其固定版本，不能删除旧 releases/bindings。配置格式或目录不兼容时明确失败，不静默切换到默认值。

API：`GET /api/admin/prompts`，`POST /api/admin/prompts/{draft,publish,rollback,restore-defaults,test}`，`GET /api/admin/prompts/tests?offset=0`，`GET /api/admin/prompts/test/{id}`。管理接口始终验证服务端管理员身份。发布接口携带页面读取的 `expected_etag` 和 `draft_etag`；恢复默认还校验页面预览的默认版本编号。409 后刷新、核对并重新保存。通用 `/api/invocations` 不接受提示词覆盖，也不接收需走专用端点的修改操作。

新试运行记录中的 `input` 保存样例，`baseline_prompt` / `draft_prompt` 保存所选模块的实际文本，`baseline_snapshot_release` 保存基线副本编号，即使基线来源是 `bundled-…` 也可以准确追溯到 `releases/`。历史列表需要 Web 角色具有该桶的 `s3:ListBucket` 权限，现有中国区 Web 角色已经配置此权限。

## 完整场景对比

管理员进入「完整场景对比」，选择一个目录场景、顶部模型及两侧版本。默认是当前生效版本与已保存草稿，也可以选择发布历史中的 B1、B2，或内置默认版本。两侧内容相同时不会启动。存在未保存编辑时先保存草稿。

点击「开始完整对比」后，两侧各调用一次真实 `generate_sets` 流程，包含材料生成、盲审、出题可行性、题目生成及原有校验和修订流程。两侧使用独立会话和固定的完整提示词快照；发布新的提示词不会改变已开始的对比。第一版仅测试文字链路，不自动合成音频。

任务由 Web 后台持有，关闭页面不会取消执行；重新进入后从场景对比历史查看。系统同一时间运行一组完整对比，重复确认同一提交不会重复启动。若 Web 服务重启或达到执行时限，记录最终显示中断，不会悄悄重跑。部署更新期间应避免启动长时间验收任务。

结果按两侧展示：材料原文、题目与答案（使用原题型版式）、材料和题目审核报告、过程事件、生成尝试/材料修改/题目修改次数、耗时和错误。次数来自实际阶段事件，不能理解为所有底层 API 调用次数。单侧失败不取消另一侧，缺少完成事件或结果不完整不会标为成功。

对比任务不写入正式批次历史，不自动选稿、提交审核或发布提示词。生成器自身的候选材料、题目和检查点仍按原有存储协议保存，使用独立的 `prompt-compare-...` 任务/分组编号。管理员的对比元数据及结果放在 `_prompt_config/scenario-runs/`，并以 `scenario-lease.json` 防止同时启动多组。两侧生成具有随机性，单次对比用于验收和诊断，不自动评出获胜版本。

接口：`POST /api/admin/prompt-scenarios`、`GET /api/admin/prompt-scenarios?offset=0`、`GET /api/admin/prompt-scenarios/{id}`，均只允许管理员。启动接口仅接受场景/模型/版本选择，服务端生成独立任务并固定版本，不接受任意 Runtime 调用参数。
