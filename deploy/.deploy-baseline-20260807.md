## 兼容性判断（RELEASES.md 警示的那一类风险）

回滚**不能**救结构不兼容的数据。逐项核过：

- `_slots/` 与 `_questions/` 是**两个新前缀**（`slot_store.py` 的模块注释也这么写），
  桶里没有任何历史对象因此改形状；
- blueprint v2 走**读写分离**的两份 schema：`blueprint.schema.json` 只管新生成（要求
  `blueprint_schema_version: 2`），`blueprint.read.schema.json` 同时接受 v1。所以回滚后旧代码
  读到的历史记录仍是它认识的形状；
- 本次部署产生的 v2 记录若在回滚后被旧代码读到，属于**已知的单向风险**：旧读侧没有 v2 分支。
  验收若失败即回滚，此时 v2 记录只有验收产生的 1 套，影响面为该套材料本身。

## 协调范围（不得只部署一部分）

前端**不是**独立部署单元：`web/Dockerfile` 在镜像里 `npm run build` 前端并 COPY 进
`/app/web/static/`。所以三者落在两个产物上：

| 产物 | 含 | 部署命令 |
|---|---|---|
| `ielts-part1-backend:<tag>` | backend（Runtime） | `backend/scripts/deploy.sh` + `deploy/runtime.sh <tag>` |
| `ielts-part1-frontend:<tag>` | web + frontend 构建产物 | `deploy/service.sh <tag>` |

**部署前实测**：线上 `:two-states-20260801` 镜像里 `web/app.py` 的 `material-questions`
出现次数为 **0**。所以只部 Runtime 会让新页签调一个不存在的接口；两个产物必须同轮上线。
