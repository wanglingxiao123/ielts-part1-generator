## 回滚命令

```bash
bash deploy/rollback.sh --runtime-image gate-fix-20260808 --taskdef 34 --dry-run
bash deploy/rollback.sh --runtime-image gate-fix-20260808 --taskdef 34
```

按镜像标签而不是 `--runtime-version 20`：DEFAULT 端点不能被重新指向某个旧版本号，回退只能用
`update-agent-runtime` 重推镜像，而那必然产生新版本号。**版本号推不出代码版本，只能认
`containerUri`。**

注意回到 taskdef 34 会同时把 `ALLOWED_EMAIL_DOMAINS` 恢复成 `*`（见下）。真要回退时如果只想
退代码不想放开域名，用 `--taskdef 32`——32 装的是 `two-states-20260801` 的前端镜像，前端会退两格。

## 顺带修掉的一处回退

taskdef **34 的 `ALLOWED_EMAIL_DOMAINS` 是 `*`**，32 和 33 都是 `amazon.com,example.com`。
`service.sh` 把这个值写成 `"${ALLOWED_EMAIL_DOMAINS:-*}"`，上一轮部署没在环境里带上它，于是
默认值静默地把公网注册重新放开了。README §5 要求公网部署必须限制域名，本轮显式带上：

```bash
ALLOWED_EMAIL_DOMAINS=amazon.com,example.com bash deploy/service.sh <tag>
```

这不是本轮改动的一部分，是发现的既有问题。`email_domain_allowed` 只在 `web/auth.py` 的
`register()` 里调用，登录不查域名，所以收紧不影响任何已注册用户登录。
